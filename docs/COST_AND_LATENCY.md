# 方案額度與延遲

## 認證與成本模式

本專案使用 **ChatGPT 登入的 Codex**，沒有 OpenAI Platform API Key，也不直接按 API 美元單價估算每堂課費用。可用量與模型權限依使用者方案／工作區決定；與同帳號其他 Codex 使用可能共用額度。不能承諾訂閱內無限量。

目前畫面顯示本次服務啟動的模型請求次數與 Codex 回報的 tokens。這不是帳戶剩餘額度，不包含其他裝置／工作階段；也不是正式帳單。後續應使用官方 `account/rateLimits/read` 查詢配額與回復時間，不自行推算。

[官方 Auth](https://learn.chatgpt.com/docs/auth) · [App Server rate limits](https://learn.chatgpt.com/docs/app-server)

## 工作量預估（規劃假設，不是實測）

假設一小時作業中實際觸發 N 次新的穩定畫面：

- 每個清楚畫面讀題 1 次，預先產生教學 1 次，約 `2N` 次模型請求。
- 低信心只讀題，先等待人工更正，不自動接續教學。
- 同題確認／不同提示層级命中短期快取時不再推理。
- 每張圖片第一次讀題、第二次教學可能各處理一次，不等於單次圖片工作量。
- 預設 30 秒最短間隔，上限不是「每小時必定 120 圖」；穩定條件、推理中與本題鎖定都會減少觸發。讀題後不因畫面變化再呼叫模型，需學生主動按下一題。
- 後端 120 次嘗試上限是每次啟動的保護。若每張都用兩次，約 60 張新圖就可能到達，不會自動增加上限。

## 延遲設計

本機預覽與活動偵測不用等雲端。停筆條件成立且尚未顯示提示時，若已有提示可直接顯示；已有第二層提示或完整說明時不覆蓋、不重複朗讀。不能把「即時顯示提示」當成「大模型保證即時辨識」。

第一版兩段推理較容易除錯，但比一次多模態完成慢。實測後再決定是否把觀察與第一層提示合併，本題則持續固定到學生主動切換下一題。維持使用者指定 Astra，不擅自降級模型。

需測量：讀題 p50/p95、教學 p50/p95、總等待、每小時呼叫數、輸入／輸出 tokens、限流次數、無故提醒次數。每個數據按相機、網路、年級、科目、圖片大小與實際模型區分。

## 失敗與重試

單一請求併發，模型回合最多等待 120 秒。失敗不自動密集重試，停止自動分析供使用者處理。Codex runtime 自身可能做網路重連；本地請求計數不是底層連線嘗試計數。達配額或模型無權限時提示，不改成 API Key、另一模型或帳號。
