# 產品規劃｜一位知道何時出聲的桌邊老師

## 1. 產品目標

學生寫紙本作業時，透過前上方 webcam 讓 AI 看到當前題目與解題過程。核心不是持續報答案，而是辨識「正在做什麼、哪一步需要協助」，提供適當提示，最後以不同情境的題目檢查是否理解。

目標環境：Mac、可固定角度的 webcam、螢幕與喇叭、網路、ChatGPT／Codex 登入與方案。第一版主模型直接採 **GPT-6 Astra**，不以小型本機模型取代教學推理。Mac 不需載入大模型權重，負責感測與互動。

適用學習階段：國小低／中／高年級、國中、高中；科目：數學、國語、英文、自然、社會、其他。多科目是共用架構，不表示各年級各題型都已有驗證。

## 2. 一次陪讀的完整流程

1. 家長或學生選年級、科目，將鏡頭固定在前上方，避免手掌長時間遮住筆跡。
2. 框選當前單一題目。姓名、學號、人臉不應入框。
3. Mac 每 0.5 秒估計區域活動；尚未讀題時，穩定至少 2 秒且距離上次分析達設定間隔才擷取；送出後固定本題，手部或紙面變化不重讀。
4. Astra 抄錄題目、圖表相關資訊與已寫答案，標記清晰度與不確定處。辨識與教學分兩個請求，便於除錯與更正。
5. 清楚且模型自評至少 0.85 時預先產生教學提示；低於門檻時先重拍或更正，0.85 只是策略門檻，不是校準過的正確率。
6. 學生確認文字後顯示 AI 作答建議；純四則式額外用程式核算。
7. 停筆達到設定時間且尚未顯示提示時，呈現已準備好的第一層提示，不覆蓋正在看的教學；不能保證 Astra 即時回覆。
8. 主動求助可到第二層提示；明確點擊後才看完整說明與複習題。
9. 學生先作答複習題，再展開參考答案。第一版為自我核對，尚未自動判改複習答案。
10. 學生理解後主動按「我理解了，下一題」，才清空本題並讀取下一題。換年級／科目也在此時操作。
11. 結束前可主動匯出本次學習紀錄；包含已完成題目的複習作答，沒有跨日學生資料庫。

## 3. 教學策略

| 階段 | 行為 | 例：24 ÷ 3 + 5 |
|---|---|---|
| 觀察 | 先確認看對題目，不打斷正在書寫 | 「我看到 24 ÷ 3 + 5，對嗎？」 |
| 提示一 | 引導注意條件、關鍵詞、單位 | 「這裡有哪些運算符號？」 |
| 提示二 | 指出下一步但避免答案 | 「先算除法，再加上 5。」 |
| 說明 | 使用者要求後才展示步驟與答案 | 24 ÷ 3 = 8，8 + 5 = 13 |
| 轉移練習 | 相同觀念、不同數據或情境 | 20 − 12 ÷ 4 |
| 延後複習（後續） | 隔日、三日、七日再測 | 依錯因與獨立完成情形安排 |

不以催促、羞辱、比較同儕推動學習；不因停筆推論「不專心」。能按「我再想一下」或暫停。不要把第一次猜對直接當作概念精熟。提示不洩漏答案目前主要靠 prompt 約束，仍需教材評測。

## 4. 多科目能力矩陣

| 科目 | 第一版大模型任務 | 評估原則 | 下一階段強化 |
|---|---|---|---|
| 數學 | 讀算式、步驟解釋、錯因提示、變式題 | 純四則精確核算；其他 AI 建議 | 代數、單位、幾何關係工具驗證 |
| 國語 | 閱讀理解、詞語、造句與段落引導 | 接受多種合理答案；不以單一範文評分 | 教師 rubric、引文定位、作文分項回饋 |
| 英文 | 文法、字彙、閱讀與句型練習 | 說明修改原因、保留替代寫法 | 語境適切性、聽說與發音 |
| 自然 | 概念、公式、實驗條件、圖表閱讀 | 不臆測缺少的實驗條件 | 科學事實來源、單位與量綱檢核 |
| 社會 | 時序、因果、地圖、材料理解 | 事實與觀點分開，缺少來源就保留 | 課綱知識庫、地圖與歷史資料引用 |
| 其他 | 一般學習問題與表達提示 | 明確標示領域不確定 | 依實際教材加入專門 rubric |

Astra 同時看到裁切圖片與確認後文字，以保留幾何圖、表格、地圖等資訊。若必要資訊在框外，應要求補拍，不能只靠文字猜。

## 5. 功能優先級

**P0：可控制、可核對的單題陪讀。** 相機、框選、穩定取樣、Astra 讀題、人工更正、提示分層、停止／清除、錯誤處理與費用節流。

**P1：真的看懂正在寫的哪一步。** 透視校正、手部遮擋、局部筆跡增量、題目切換追蹤、科目 rubric、逐題用量與延遲。

**P2：學會而不是只完成作業。** 經同意的概念紀錄、錯因分類、間隔複習、學習成效比較、家長可理解的摘要。

**P3：自然互動與部署。** 有打斷處理的語音問答、macOS 簽章安裝包、設定精靈、更新機制、班級與家長權限。

## 6. 成功指標與驗收門檻（目標，尚非測量結果）

先由教師標註代表性測試集，每科至少 50 題，涵蓋三種年齡段、清楚／模糊／遮擋／未完成／錯誤／多解。避免只用印刷算式證明手寫能力。

| 面向 | 試用前門檻 |
|---|---|
| 視覺 | 可判讀照片的題意與作答擷取正確率 ≥95%；另報拒答率與條件分布 |
| 判讀 | 人工確認題目後的「錯誤判為正確」≤2%，按科目報告，不混成單一平均 |
| 不確定 | 模糊／遮擋題 ≥95% 會要求確認或補拍 |
| 教學 | 教師審查提示適切率 ≥90%；前兩層洩漏完整答案 ≤2% |
| 提醒 | 無故打斷 ≤1 次／10 分鐘；思考延後確實兩分鐘有效 |
| 系統 | 預備好提示時，停筆門檻達成到 UI 提示 p95 <1 秒；雲端 p50/p95 另報 |
| 成本 | 逐次記錄 usage，設定每堂課方案用量上限並證實達上限會停止 |
| 學習 | 不能只看做完速度；記錄無提示變式題與延後題正確率 |

正式兒童試用前需完成監護人同意、資料處理政策確認與教師審查。這是產品部署工作，第一版不宣稱已完成。

## 7. 主要風險與設計選擇

- **模型自信但看錯字**：先顯示 OCR，低信心不判分，保留人工更正。
- **提示太頻繁**：穩定閘門、提醒冷卻、延後與暫停；後續用實拍資料調門檻。
- **只照答案寫**：兩層提示、明確揭露答案、要求變式練習。
- **費用堆積**：只看變更的 ROI、單一併發、有限快取、呼叫上限；方案配額感知待 P1。
- **雲端等太久**：本機即時 UI、先準備提示；不以影片串流持續餵大型模型。
- **光影／手部被當成筆跡**：現階段明示是活動量 heuristic；P1 才做筆尖與手部追蹤。
- **題面包含指令**：當成學習資料，模型無工具與程式執行權；用輸出 schema、長度限制與 adversarial tests。
